# 红果短剧 脱机下载 —— 端到端复现手册(2026-06-29)

> 目标:**不安装/不运行红果 app、不用 frida** 完成「搜索 → 取直链 → 下载 → 解密 → 可播 mp4」全链路。
> 本文把分散在 `unidbg-sign/README.md`(签名)与 `docs/VIDEO_DECRYPTION_RE.md`、`docs/逆向复盘-spade解密`(解密)
> 的成果串成一条可复现的流水线,并记录本次补齐的两个关键缺口(音频轨解密、重封装可播)。

---

## 0. 全链路总览

```
                     ┌─ unidbg 离线签名服务(FqTrace serve)──┐
hongguo.py ──签名──▶ │  番茄海外 libmetasec_ml.so @0x168c80   │ ──X-Argus/X-Gorgon...──▶ fqnovel 网关
   │                 └───────────────────────────────────────┘
   │ search → get_episodes → multi_video_model
   ▼
video_model { main_url(密文CDN), encrypt_info{ kid, spade_a }, ... }
   │
   ├─ 下载 main_url ──────────────▶ 密文 mp4(CENC: encv/enca/senc/tenc)
   │
   └─ 离线解密(纯算法, 无 app):
        spade_a ──unwrap_spade──▶ content key(AES-128)
        每轨 senc 首样本 ──▶ base_iv(视频/音频各一个)
        AES-128-CTR 逐样本解密(视频轨 + 音频轨)
        ──ffmpeg -c copy 重封装(encv→hvc1, 删 senc/sinf)──▶ 可播 mp4
```

**两个 app 依赖都已拆除**:
1. **签名** → 跨 app 链路:用同后端(fqnovel.com)的番茄海外签名器代签,网关只验签名有效性、不做 app↔证书强绑定。见 `unidbg-sign/README.md`。
2. **解密** → 纯算法离线:`spade_a` 本地 unwrap 出 content key,无需 KEK / 无需播放器。

## 2. 启动离线签名服务

```bash
cd unidbg-sign
mvn -DskipTests package
java --add-opens java.base/java.lang=ALL-UNNAMED \
  -cp target/unidbg-sign-1.0-jar-with-dependencies.jar \
  com.hongguo.sign.FqTrace serve 9099
# → [*] unidbg 离线签名服务已启动: http://127.0.0.1:9099/sign
```

协议同原 frida 签名服务:`POST /sign {"url":..,"headers":{..}} → {"X-Argus":..,"X-Gorgon":..}`。
模拟器单线程,服务内部对签名串行加锁;首次冷启约数秒,之后常驻热签。

> 注:9090 端口可能被 xinge Go 服务占用,换 9099 等空闲端口。

## 3. 跑 hongguo.py(零改动)

`hongguo.py` 的 `sign()` 已支持 `SIGN_SERVERS`(来自环境变量 `SIGN_SERVER`),指向上面的服务即可:

```bash
export SIGN_SERVER="http://127.0.0.1:9099"
python hongguo.py search "亮亮就业"
python hongguo.py download <series_id> 1-3
```

API 链路:
- `search` → `/reading/bookapi/search/tab/v` → 拿 `book_id/series_id`
- `get_episodes(series_id)` → `/novel/player/multi_video_detail/v1/` → 每集 `vid`
- `get_video_urls(vids)` → `/novel/player/multi_video_model/v1/` → 每轨 `main_url + encrypt_info.spade_a`

**验签必要性实测**(`/reading/bookapi/search/tab/v`):无签名 → HTTP 200 但 **body 空**(网关静默拦截);带跨 app 签名 → `code=0` 真实数据。

## 4. 离线解密(本次补齐:音频轨 + 重封装)

核心:`frida/offline_decrypt.py:offline_decrypt(spade_a, 密文.mp4, 输出.mp4)`

```python
import sys; sys.path.insert(0, "frida")
import offline_decrypt as OD
OD.offline_decrypt(spade_a_b64, "ct.mp4", "out.mp4")
```

内部步骤:
1. `unwrap_spade.spade_to_key(spade_a)` → content key(纯字节变换,无 KEK,flag 不确定时自动两种都试)。
2. `oracle.verify_key_iv` → 用视频轨 NAL 自证确认 key 正确。
3. `decutil.decrypt_av(ct, key, raw)` → **遍历 moov 每个 trak**,凡轨内有 `senc` 盒即视为加密轨:
   - 该轨 base_iv = **轨内** senc 首样本 IV 高 8 字节(视频/音频各自独立!);
   - `oracle.parse_track_samples(d, handler)` 解析该轨样本偏移(`stsz/stco|co64/stsc`);
   - AES-128-CTR 逐样本解:`iv = (base_iv + sample_index) << 64`,全样本满帧加密(无 subsample 明文头)。
4. `decutil.remux_playable(raw, out)` → `ffmpeg -c copy -tag:v hvc1` 剥离 CENC 信令盒。

### ⚠ 本次踩的两个坑(原管线缺陷,已修)

| 坑 | 现象 | 修复 |
|----|------|------|
| **只解视频轨** | 老 `decrypt_full` 仅解 `vide` 轨,音频 `enca` 仍是密文 → **有画无声**(aac 解码报错、RMS=0) | 新增 `decrypt_av` 遍历所有加密轨,音频轨用**自己的** senc base_iv(与视频轨不同!)解密 |
| **不剥加密盒** | 解密只改 mdat 样本字节,`stsd` 仍是 `encv`、`senc/sinf` 仍在 → 严格播放器(如系统播放器)当成加密 **黑屏**(ffmpeg/VLC 宽松能放) | 新增 `remux_playable`,`encv→hvc1` 并删 `senc/sinf/saiz/saio` |

实测(亮亮就业 第01集,1080p):`视频 4200/4200 NAL 合法; 音频 3019 样本已解`,输出无 encv 残留、音频 RMS≈4936(正常人声)、任意时间点可解帧。

## 5. 一键脚本示例(搜索→下载→解密→可播)

```python
import sys, json, requests
sys.path[:0] = ["frida", "."]; sys.path.insert(0, "../hongguo/frida")  # 路径按实际仓库布局
sys.argv = ["hongguo.py"]; import hongguo
import offline_decrypt as OD

SID = "<series_id>"
meta, eps = hongguo.get_episodes(SID); vid = str(eps[0]["vid"])
body = {"biz_param": {"need_all_video_definition": True, "video_platform": 1024,
        "detail_page_version": 0, "device_level": 3, "disable_digg_stat": False,
        "disable_video_relate_book": False, "need_mp4_align": False,
        "use_os_player": False, "use_server_dns": False},
        "mixed_video_id_map": {"1": [vid]}}
vm = json.loads(hongguo.api("POST", "/novel/player/multi_video_model/v1/", body=body)["data"][vid]["video_model"])
best = max(vm["video_list"], key=lambda t: t["video_meta"].get("size", 0))   # 选最高清
open("ct.mp4", "wb").write(requests.get(best["main_url"], headers={"user-agent":"Mozilla/5.0"}, verify=False).content)
OD.offline_decrypt(best["encrypt_info"]["spade_a"], "ct.mp4", "第01集.mp4")    # → 可播 mp4(含音轨)
```

环境前置:`SIGN_SERVER` 指向签名服务、`PYTHONPATH` 含 `hongguo.py` 与 `downloader` 所在目录。

| 文件 | 作用 |
|------|------|
| `unidbg-sign/src/main/java/com/hongguo/sign/FqTrace.java` | 跨 app 签名器 + `serve` 常驻服务 |

| `frida/oracle.py` | `parse_track_samples`(任意轨样本解析)、`verify_key_iv`(NAL 自证) |

## 7. 已知边界

- **ver2 / AES-GCM 视频**:`unwrap_spade` 仅支持 v1;ver2 会在 unwrap 阶段报错(目前未见红果使用)。
- **token 过期**:仍需红果自己的有效 `x-tt-token`(`config.json`);签名跨 app,登录态不跨 app。`hongguo.py` 的 `refresh_session` 走签名服务 `/grab`(需 app 在场)抓新 token —— 纯脱机场景需另行维护 token。
- **无 ffmpeg**:`remux_playable` 退化为保留未重封装的明文(`*.raw.mp4`),仅 ffmpeg/VLC 等宽松播放器可放。
